# Changelog

This project uses [semantic versioning](https://semver.org/).

## Unreleased

- README in Persian, Arabic and Turkish.
- The Windows app starts: one exe with Setup, Monitor, Sync, Connect and Uninstall pages, plus Preferences and About. Only Setup has content so far; the other pages say they come in a later version.
- Setup shows your existing CPFS install as found, read-only: the settings file, the SMB account, share, firewall rules, tasks, security settings, networks, drive letters, shortcut and data folder. It changes nothing on Windows.
- "Continue as administrator" restarts CPFS with administrator rights to read what needs them, and shows the drive letters in use in your own session.
- Theme (System, Light, Dark), language and a font per language are saved for your Windows account. English is complete; Persian, Arabic and Turkish can be picked but still show English.
- About shows the version, the log with Open log and Copy report, and the licences: MIT for the code, the brand files excluded, and the third-party notices.
- Settings files written by every earlier CPFS version are read, including single-item lists and files with or without a byte order mark.
- README: tagline, description and the licence of the brand files and fonts.
- Setup reads the SMB account in milliseconds instead of about 20 seconds, and each section appears as soon as it has been read. The log shows how long each one took.
- On Windows 11 the app uses Segoe UI Variable as intended: the Text size for body text and the Display size for page titles. Windows 10 keeps Segoe UI.
- Numbers and dates follow the app's language, not the Windows regional format. About shows the program file's size and date.
- Connect page: every address of the PC (`ComputerName.local`, each Wi-Fi or LAN address, the VPN address and MagicDNS name), each marked as same-network or VPN, with steps for Windows, macOS, Linux, Android and iPhone/iPad, a copy button for every value and QR codes drawn by the built-in encoder. No password appears anywhere. Works without administrator rights.
- Monitor page (administrator): connected devices, per-share and server traffic, open files and failed network sign-ins of the last 24 hours with their reason, refreshed every 2 seconds. Disconnect closes one device's session after you confirm it; it changes no setting.
- About labels the tagline and the motto.
- Monitor: Disconnect now confirms that the device's session has closed, so a successful disconnect no longer shows as failed on Windows builds where `ForceClose` returns no code.
- Preferences shows where your preferences are saved in a card of its own, with the path wrapping in a narrow window.
- README: the motto, with tagline and motto labelled in all four languages.
- Connect page: the client cards sit two to a row when the window is wide enough to read them, and one to a row when it is narrower.
- Setup page: each section folds open and closed, with its status and a one-line summary in the header; sections with an error or that need administrator rights open on their own, and Expand all and Collapse all work on every section at once.
- The log records each failed network sign-in the first time Monitor shows it (time, account name and reason code), and the result of every Disconnect.
- The app uses the final CPFS app icon.
- Setup: Expand all and Collapse all use a matching pair of icons.
- Monitor: Disconnect no longer ends in an error after the device was dropped, and any failure of Disconnect is shown on the page instead of the crash report.
- Monitor: a connected device shows its network name under its IP when Windows can look one up, and you can give a device your own name (Name this device, Rename, Forget name). Names are saved for your Windows account in `%LOCALAPPDATA%\CPFS\devices.json`, keyed by the device's MAC address, or by its IP when it has none (VPN).
- Setup shows a plan: a form with your saved install as the starting values (folder, share name, SMB account, password, strict mode, Auto-Private, drive letter and name, shortcut name) and, for each setting, whether Setup would keep, change, create or remove it, or ask you first, with the reason. Changing a field updates the plan. Apply is not active yet, and nothing is written to Windows or to `config.json`.
- The plan follows CPFS's safety rules: the backup is taken only on the first Setup, a setting already stricter than CPFS's is kept, no network becomes Private and no account or share CPFS didn't create is used or removed unless you tick it, the VPN rule is bound to the VPN adapter, the lockout threshold is set only when lockout is off, and only free drive letters are offered.
- About and the log show the version as `0.5.0-dev1 (3d20e71)`: the test build number and the short commit it was built from.
- Builds are checked on Windows by GitHub Actions: the solution is built and tested, and the exe runs a headless self-test that reads the Windows state and builds the plan without changing anything.
- Setup: the SMB server settings (SMB2/SMB3, rejecting unencrypted access, the SMB1 protocol) are read through `GetConfiguration`, with the LanmanServer registry values as a fallback, so they no longer show "Could not be read".
- Setup: a setting Windows refuses to show without administrator rights, such as the audit of failed sign-ins, is marked "Needs administrator to plan" instead of "Could not be read".
- Setup's plan now covers the share's permissions (only the SMB account keeps access; anyone else is removed only if you tick it) and the computer name: the current name is kept, a rename waiting for a restart is shown, and so is a saved name that differs from the current one.
- The log lists each plan item that is not Keep, with its action and reason, so a support log shows what Setup would do.
- Setup can now apply its plan, as administrator: after a summary you confirm, it creates or updates the SMB account (the password goes straight to Windows and is never kept), the folder permission, the share (changed in place, not recreated), the SMB server settings, the security settings, the firewall rules and the networks you tick, and locks `ProgramData\CPFS`. Each item shows its progress; the first failure stops the run, and everything done before it is already recorded in `config.json`. Drive letter, drive name, desktop shortcut, Auto-Private and computer name are shown as coming in 0.6.0 and skipped.
- `config.json` is saved after every change, atomically, in the format the 0.2.0 Uninstall script reads. The original settings are recorded once, on the first Setup, and never overwritten.
- Setup and Uninstall create a Windows restore point first (ticked by default). If Windows skips it, for example within 24 hours of the last one, or System Protection is off, CPFS asks before going on.
- Uninstall page: shows what it would undo from the backup and what Setup recorded, then undoes it. Your files are never deleted; ownership of files the SMB account owned goes back to you only if ticked; the account's profile folder is offered only for an account CPFS created, unticked; Windows' own firewall rules come back on in every case; SMB1, Guest and the failed sign-in audit stay as they are. A copy of `config.json` goes to your Documents folder first.
- A desktop shortcut or drive that an earlier install made and you removed is offered again as an unticked choice, never recreated on its own.
- The window title shows the version, and About has a Copy version button.
- The Windows build in CI now runs Setup and Uninstall on the runner and checks that everything is restored, and that Windows PowerShell 5.1 reads the written `config.json`.
- Setup writes each CPFS firewall rule switched off, reads it back and switches it on only when Windows took every field (adapter, profiles, addresses, port, protocol, direction). A rule that reads back differently is removed and Setup stops with the reason, so the VPN rule can never be left open on every network.
- A change Windows refuses shows as "Refused by Windows" with its reason and counts as not done, no longer as coming in 0.6.0. Giving file ownership back shows "Partly done" with its counts when some files failed, and stops Uninstall when none could be changed.
- Uninstall removes a share only when it is CPFS's own (the recorded name and folder, or CPFS's description); a share that only has the same name is an unticked choice.
- Uninstall keeps an account that `config.json` names but never recorded as created, unless you tick it.
- Uninstall leaves a setting whose backup has no original value as it is, instead of writing 0.
- Uninstall always saves a copy of `config.json` to your Documents folder before it changes anything, as a new file that never replaces another, and refuses to run when `config.json` names a shared folder Setup would refuse (a drive root, Windows, Program Files or ProgramData).
- The password boxes are emptied after every Apply, also when it fails.
- Setup sets and checks each property of a new SMB account itself (enabled, password never expires, member of Users, not an administrator, hidden) instead of relying on Windows defaults; on some Windows editions a new account was not put in Users.
- Copy buttons show the result on the button itself (a checkmark and "Copied" for a moment, or an error mark with the reason) instead of a large bar over the page.
- About: the copy button for the version sits at the end of the version line.
- Setup: an eye button beside each password box shows or hides what you typed; the text is hidden again when the window loses focus or Apply starts, and it can't be copied while shown.
- Setup: the drive and shortcut fields and their "Create it again?" ticks are greyed out, keeping their values, and their plan items carry a note, because creating the drive and the shortcut comes in version 0.6.0.
- The question after a restore point Windows did not make keeps its full button labels: the buttons share a row when they fit and stack when they don't, in any language and text size. Its progress row says Skipped, in a warning colour, instead of Failed.
- Setup and Uninstall show settings in words instead of raw values: "Hidden from the sign-in screen: visible → hidden", security values as off, on or a level, a lockout threshold of 0 as off, the Server service start type by name, and the settings that differ on a share or firewall rule by name.
- Monitor: the per-share traffic adds up every counter instance of a share and uses whichever of the sent or read byte counters Windows fills, and the log lists the share counters Windows returns once per run.
- Only one CPFS window opens per Windows session: starting CPFS again brings the open window to the front, or says that CPFS is already open as administrator when Windows does not allow that.
- Setup is simpler, on one page for a first install and later runs: the folder (with a Browse button that refuses the same folders as the field), share name, account and password; strict mode, networks, drive, shortcut and computer name under a collapsed More options; Your decisions with every question as a tick box; one sentence on what will change, naming first what affects how phones connect; and one button, Set up or Apply. The full plan and the progress list sit under Show details.
- Uninstall has the same shape: a summary sentence, Your decisions, the restore point tick and the Uninstall button, with the full plan under Show details. The confirmation dialogs of both pages are three short lines (how many changes, that they can be undone, and the restore point), with the list of changes under Show details.
- After Setup or Uninstall, the result names the number of changes made and every change Windows refused or did only in part, with Windows' own words and a Copy report button. After a first Setup, Connect a device opens the Connect page.
- New Advanced page in the navigation footer: what CPFS reads on this PC, the hand-over check, the diagnostics and log that used to be on About, where preferences are saved, and an "Always show details" switch. About keeps the brand, the version, the homepage, Copy report and the licences.
- Monitor: traffic is shown per connected device, from Windows' per-session counters, instead of per share; a device whose counters can't be matched to it for certain says "Not available". The log lists those counters once per run and compares the devices' traffic with the server totals once. The intro text and the "Updated" time are gone; Down and Up explain their direction in a tooltip.
- Setup's fields line up in one column at every window size: each input box has the same width and edges, with Browse, show password and clear buttons in the same slot beside it; on a narrow window the field moves below its title.
- One password box instead of two, with the show button kept; the share name, account and password fields each get a clear button.
- The summaries count firewall rules by what happens to them (created, corrected, removed, turned off, turned back on), and Uninstall's says when the SMB account is kept.
- A Windows error message in a result now stands on its own line instead of inside a sentence.
- Buttons keep their theme colours while pressed: in the dark theme, Browse, clear, show password and the other buttons no longer turn their text and icon black.
- The Setup and Uninstall confirmations show the list of changes with a "Show details" tick box, and only their own Apply or Uninstall button confirms: no button reacts to Enter, and Esc, Cancel or the window's close button never start anything. The log records how every dialog was closed.
- The restore-point question has no default button any more, so Enter alone no longer continues without a restore point. The log gives the newest restore point's time with its real UTC offset instead of marking local time as UTC.
- Monitor: a device's buttons (Name this device, Disconnect) sit in one column of equal widths beside its details, and move below them in a narrow window. Disconnect no longer reacts to Enter.
- Connect: each device card has a QR code button that opens the code large in a dialog, with the text it holds and a copy button; the cards no longer show the codes themselves.
- The restore point and failure messages put Windows' own words on a line of their own.
- Monitor: the once-per-run comparison of device and server traffic waits for an interval it can actually compare, however late in the run that comes.
- Buttons look like Windows 11 buttons again in every theme: in the previous test build the fix for the pressed colour made every button fall back to the plain grey Windows button and the clear and show password buttons lost their icons.
- Setup: the drive letter, drive name and desktop shortcut fields are in the main list after the password, aligned with the other fields; More options keeps strict mode, Auto-Private and the computer name. Features not available yet say so without a version number.
- The Setup and Uninstall confirmations list each change on its own line after a dash, and a long line wraps under its text.
- Monitor: a connected device shows "Active now" or "Idle for" a time instead of its own traffic, which Windows doesn't count per device; the server totals say they cover all devices, and name the device when only one is connected.
- Setup creates the drive letter, its name in File Explorer and the desktop shortcut: the drive is mapped for every session after a restart and in your own session right away, a new letter, name or shortcut name replaces only the ones CPFS recorded, a letter or file CPFS didn't create is never taken over, and Uninstall removes exactly what was recorded.
- The Setup and Uninstall confirmations show the list of changes under a Show details dropdown again; opening or closing it never confirms or closes the dialog, and the log records how it was used.
- "Always show details" and the preferences location are gone from Advanced; every Show details starts closed.
- About shows the tagline under the app name, a "Source code on GitHub" link and a Check for updates button; the motto moves to the top of the navigation pane while it is open.
- Optional update check: About can ask GitHub whether a newer release exists, and Preferences can do it at each start (off by default). Nothing is downloaded or installed.
- Items that need administrator rights carry the Windows shield instead of a separate warning, and so does Setup's main button until you continue as administrator.
- Setup and Connect say "SMB username" and "SMB password" for what devices sign in with.
- Setup and Uninstall remove a `CPFS-RunAsUser` task left in the Task Scheduler's root folder by a run that stopped halfway or by the 0.2.x scripts.
- The update check no longer follows redirects: any redirect counts as "Couldn't check for updates", so the request can only ever reach api.github.com.
- Setup no longer replaces a drive name you gave CPFS's drive after the first Setup without asking: it asks first, unticked, because Uninstall would put back the older original.
- When no signed-in desktop user is found, the drive step reads "Couldn't add the drive to your current session; it appears after a restart" instead of "Refused by Windows", and Uninstall notes that a removed drive letter may stay in File Explorer until Windows restarts.
- The drive gets the CPFS icon in File Explorer and the desktop shortcut gets the CPFS icon, both from a copy of the icon in `ProgramData\CPFS`, so they keep it when the exe moves. An icon someone else gave the drive letter is replaced only when you tick it, and Uninstall puts it back.
- Setup says under the drive name that File Explorer may show the name of the folder's disk instead: Windows uses the disk's own label for a drive mapped to a folder on it.
- Setup, Uninstall and Monitor show "Reading this PC…" with a progress ring until the first reading is ready, and Setup's fields stay off until then.
- Monitor keeps a file in the open files list for about 10 seconds after it closes, dimmed and marked "Closed", so quick transfers can be seen.
- About shows the version, homepage and source code as aligned rows like Windows Settings, with plain links.
- The motto is no longer shown at the top of the navigation pane.
- The QR code dialog leaves more room above the Close button.
- About shows a globe icon beside the homepage link.
- After Apply, Setup no longer shows the changes it just made for a moment while it reads the PC again.
- Setup adds the shared folder to File Explorer's navigation pane, under the drive name you chose and with the CPFS icon, so the name shows even when the folder's disk has a label of its own. It has its own switch (on by default) and works without a drive letter; Uninstall removes it only while it still opens the recorded folder.
- Setup and Uninstall read the PC again when you come back to them after the other one changed Windows, and again when you press Set up, Apply or Uninstall. If the summary would change, CPFS shows the new one with a warning instead of the confirmation, so a change is never made from an out-of-date reading (an Uninstall followed by Set up failed at the account's password).
- When the button is off because an answer is missing or wrong, the summary says what to do, such as entering the SMB password, and no longer says that items can't be checked yet; the hint under the button no longer repeats it.
- A step that fails shows Windows' message on a line of its own, without the error's type or the name of the Windows function; the log keeps both.
- Monitor: a Recent activity card lists files and folders added, changed, renamed or deleted in the shared folder while Monitor is open, from any device or from this PC, so small files copied from a phone show up even when they are open too briefly to appear under Open files. It keeps up to 200 changes from the last 24 hours in memory only, and the log records counts, never file names.
